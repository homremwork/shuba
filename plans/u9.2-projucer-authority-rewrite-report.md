# U9.2 Projucer authority-rewrite stop report

## Status

**U9.2 is paused before its second clean generation and before any generated-contract or mutation-test change.** The currently present [`Builds/Android`](../Builds/Android) and [`JuceLibraryCode`](../JuceLibraryCode) trees are ignored, first-generation diagnostic output only. They are neither source authority nor acceptable release evidence.

## Observed evidence

1. The U9.1 source gate passed: [`third_party/JUCE`](../third_party/JUCE) resolved to the required `9.0.1` commit `e18f7f506c0b96f2c738a0bcd7fe6467a5005ad8`, and [`build-projucer.fish`](../tools/release/build-projucer.fish:15) accepted the pinned cached Projucer fingerprint.
2. The JUCE 8 generated baseline passed [`check-generated-android.fish`](../tools/release/check-generated-android.fish:3), contained 256 files, and had a tree digest of `84caff69e3f3eb9a64fc14b329cc4a0b08107dd1fecdbbba9ebabb67598b7973`.
3. The first clean JUCE 9 generation removed only the ignored ownership roots through [`generate-android.fish`](../tools/release/generate-android.fish:41). It produced 47 files before the intentionally stale generated-file-inventory assertion stopped validation.
4. The first output tree digest is `e876d69030de3b278751ac7791c5a80c09dd610fcada337fd4385b3a1a430d46`.
5. The authority hash changed during `Projucer --resave` from `a0f5072370be20c0577917ed6cece14de6d4f3aff58f529c9391c34aae2a0b2e` to `8f7fb4986b5426813922f3ac5635578b5ad695e07788c65de4959e35a2677bdc`.
6. Inspection found a formatting/canonicalization rewrite of the Android exporter, consolidating the explicit JUCE 9 `gradleVersion="8.13"` and `androidPluginVersion="8.13.2"` exporter attributes adjacent to the custom Gradle content. The release contract values, Android API 34, NDK pin, ABI, permissions policy, modules, source inventory, and application identity were not observed to change.

The existing rule at [`U9.2 rollback/stop`](juce-9-migration-plan.md:86) treats *any* [`Shuba.jucer`](../Shuba.jucer:3) mutation as a stop. This behavior is correct: it prevents a generator upgrade from silently changing authority. It also means a narrowly approved decision is required before U9.2 can continue.

## Decision required

### Option A — Preserve strict byte identity

Restore the pre-resave byte representation of [`Shuba.jucer`](../Shuba.jucer:3), discard the diagnostic output, and retain an unconditional no-rewrite requirement.

- **Benefit:** the strongest possible guard against hidden Projucer authority drift.
- **Cost:** JUCE 9 generation cannot complete while it consistently canonicalizes this representation. Continuing would require generator modification or a manually maintained descriptor, both contrary to the generated-output ownership boundary.
- **Recommendation:** reject unless byte identity is a higher priority than completing the JUCE 9 migration.

### Option B — Adopt the JUCE 9 canonical descriptor as tracked authority

Accept the one reviewed canonical exporter representation in [`Shuba.jucer`](../Shuba.jucer:274), then change U9.2’s rule from unconditional byte preservation to *one explicitly authorized semantic-normalization transition*, followed by strict byte preservation for all subsequent generations.

- **Benefit:** preserves source authority, supports Projucer’s canonical JUCE 9 representation, and still rejects any unreviewed source mutation.
- **Cost:** requires a precise allowlist and proof so the exception cannot hide later changes.
- **Recommendation:** adopt with the controls below.

### Option C — Allow arbitrary Projucer rewrites during U9.2

Continue whenever regenerated outputs pass.

- **Benefit:** minimal tooling effort.
- **Cost:** silently broadens generator authority over tracked project settings and defeats the current safety property.
- **Recommendation:** reject.

## Recommended controlled transition for Option B

1. Treat the canonical descriptor as a reviewed **source-authority change**, not a generated-file update and not a runtime change.
2. Capture a normalized XML attribute projection of the Android exporter before and after the transition. Acceptance permits only the reviewed ordering/placement normalization of `gradleVersion` and `androidPluginVersion`; every name/value pair must remain identical.
3. Run a clean regeneration using the canonical tracked authority. The generator must then leave [`Shuba.jucer`](../Shuba.jucer:3) byte-identical.
4. Run a second independent clean regeneration. The authority hash, output inventory, and content digest must exactly match the first clean result.
5. Retain the current hard stop in [`generate-android.fish`](../tools/release/generate-android.fish:85) for every post-transition resave. Do not add a permissive exception in production generation tooling.
6. Only after those gates pass, update [`generated-android-validation.fish`](../tools/release/lib/generated-android-validation.fish:47) and [`test-generated-android.fish`](../tools/release/tests/test-generated-android.fish:23) for documented JUCE 9 output facts and new mutation coverage.

## Required plan wording if Option B is approved

Amend U9.2 as follows:

- The entry gate includes a reviewed, tracked JUCE 9 canonical form of [`Shuba.jucer`](../Shuba.jucer:3), with the Android exporter’s attribute-value projection unchanged from the accepted U9.1 contract.
- The first authorized canonicalization is evidenced by projection comparison and a clean resave of that new tracked authority.
- After canonicalization is committed as authority, any further [`Shuba.jucer`](../Shuba.jucer:3) byte mutation remains a stop/rollback condition exactly as currently specified.

This wording retains the intent of the original stop condition while allowing only the minimal transformation that JUCE 9 has demonstrated as necessary.

## Non-goals

- Do not update generated inventories, native CMake assertions, or mutation tests while paused.
- Do not build Android, alter runtime C++23 code, manually patch generated files, alter permissions, or change the release contract.
- Do not use the diagnostic outputs as a baseline for acceptance until two clean canonical-authority generations agree.
